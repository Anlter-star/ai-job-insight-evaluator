# 数据集上下文与 Prompt v3 调优报告

版本：v3  
运行日期：2026-10-18  
数据：`data/validation/validation_dataset.jsonl`（9条已见调优数据）  
模型：DeepSeek Flash  
方法：`llm:deepseek-flash:job_extraction_v3`

## 本轮改动

1. 为18条记录新增 `input.dataset_context.employment_type`，把采集阶段已经确认的用工类型作为模型可见输入。
2. `compose_source_text` 同时传入数据集上下文、页面顶部结构化信息和职位正文。
3. 规则提取器升级为 `keyword_rules_v3_context`，优先采用已确认的数据集上下文。
4. Prompt升级为 `job_extraction_v3`，收紧在校生判断、岗位分类、必需/加分字段边界和技能标签粒度。
5. v3结果写入 `results/tuning_v3/`，不覆盖首轮盲测和v2结果。

数据集上下文是静态写入记录的采集事实，不从 `gold` 动态生成。未来处理混合用工类型数据时，应逐条填写；无法确认时使用 `null`。

## 主要结果

| 指标 | Prompt v2 | Prompt v3 | 变化 |
| --- | ---: | ---: | ---: |
| 单值字段宏平均准确率 | 93.83% | 100.00% | +6.17个百分点 |
| 技能微平均 Precision | 15.60% | 19.38% | +3.78个百分点 |
| 技能微平均 Recall | 30.14% | 34.25% | +4.11个百分点 |
| 技能微平均 F1 | 20.56% | 24.75% | +4.19个百分点 |
| 严格额外项率 | 84.40% | 80.62% | -3.78个百分点 |
| 潜在无原文支持项率 | 13.48% | 19.38% | +5.90个百分点 |

v3的9个单值字段均为9/9正确：岗位类别、用工类型、地点、日薪、最低学历、在校生身份、毕业年份、每周到岗天数和实习期限。

## 技能字段结果

| 字段 | v2 F1 | v3 F1 | 变化 |
| --- | ---: | ---: | ---: |
| 必需硬技能 | 13.91% | 22.02% | +8.11个百分点 |
| 必需工具 | 48.00% | 45.45% | -2.55个百分点 |
| 加分硬技能 | 24.39% | 27.78% | +3.39个百分点 |
| 加分经历 | 18.18% | 17.14% | -1.04个百分点 |

Prompt v3减少了总体输出项数量，并提升了必需硬技能和加分硬技能的匹配率。不过，工具字段与加分经历略有下降，主要仍是标签合并粒度和字段归属不一致：例如 `NumPy、SciPy或SymPy` 被拆成三个工具，`Oracle或MySQL` 被拆成两个工具；部分专业背景、身份条件和复合经历被当作独立加分项输出。

## 风险与结论

- 当前9条数据已经参与多轮提示词和标准答案调优，因此本结果只能说明训练内调优效果，不能作为泛化能力结论。
- 潜在无原文支持项率上升到19.38%，说明“单值字段全对”并不代表整体抽取已经稳定。后续应限制每个技能字段的输出数量，并加入复合标签合并和专业背景排除规则。
- 评测器的归一化别名尚未覆盖本轮大量近义表达，因此严格分数同时混合了真实错误与标签粒度差异。别名只能基于独立审核维护，不能为了追分自动吸收模型输出。

## 下一步

1. 冻结 Prompt v3 和当前规则，不再用这9条数据继续直接调参。
2. 新建一批从未参与开发的冻结测试集，保持三类岗位的均衡分布，并逐条保存页面顶部元数据和数据集上下文。
3. 在新测试集上一次性比较规则v3、Prompt v2和Prompt v3，重点观察单值字段准确率、技能F1和潜在无原文支持项率。
4. 若仍需开发 Prompt v4，应另建训练/调优集，并增加技能输出上限、复合标签示例和专业背景排除规则。
