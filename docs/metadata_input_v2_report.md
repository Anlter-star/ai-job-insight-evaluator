# 页面顶部元数据输入修复报告

版本：v2  
日期：2026-10-18

## 问题

第一版数据虽然在人工标准答案和证据中记录了页面顶部的日薪、学历、到岗天数和实习期限，但模型输入只包含标题、公司、城市、职责、要求和加分项。因此正文未重复这些信息时，规则和大模型无法提取；正文与顶部冲突时，也无法执行“顶部优先”的标注规则。

## 修复

1. 在18条数据的 `input` 中新增独立的 `page_metadata`：地点、日薪、学历、每周到岗天数和实习期限。
2. `compose_source_text` 将顶部元数据与正文一起传给模型，运行时不读取 `gold`。
3. 规则提取器升级为 `keyword_rules_v2_metadata`，顶部字段存在时优先采用顶部值。
4. Prompt升级为 `job_extraction_v2`，明确顶部/正文冲突处理规则。
5. 输出Schema新增 `salary_yuan_per_day`，毕业年份新增 `exact` 表达。
6. 原验证结果保留在 `results/validation/`；v2结果写入 `results/validation_v2/`，避免覆盖。

## 标注审计与剩余问题

- 本批数据的采集范围已确认全部为实习岗位。原标准答案把4条标题未明示“实习”的记录标为`null`，属于标注错误；修正后 Prompt v2 的 `employment_type` 准确率为100%，不是过度推断。
- Prompt v1与规则方法没有获得或利用这项数据集级上下文，因此用工类型准确率均为55.56%。若未来处理混合用工类型的数据，应把经过确认的采集上下文显式写入输入，不能仅靠页面形态猜测。
- `job_category` 从88.89%下降到77.78%，相邻岗位边界仍不稳定。
- `student_status` 从88.89%下降到66.67%，模型把应届生或实习页面语境推断为在校生。

下一版应把“已确认的采集范围”设计为独立输入上下文，以便区分可靠的数据集级标签和基于页面形态的猜测；`student_status`仍只能依据“在校/在读”等明确表述。
