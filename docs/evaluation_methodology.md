# 评测方法（v2）

## 为什么需要第二版评测器

第一版对技能类字段采用字符串完全匹配。这种方法可复现，但会把“AI Agent开发”和“开发AI Agent”等语义相同、表达不同的结果判为错误；同时，第一版把所有标准答案之外的预测都称为“幻觉”，无法区分有原文依据的标签粒度差异和真正无依据的生成。

第二版保留严格指标作为基准，并增加归一化匹配和原文依据诊断。两套指标同时报告，不用归一化结果覆盖原始结果。

## 三层评测

### 1. 严格匹配

- 单值字段采用完全相等比较，包括岗位类别、用工类型、地点、日薪、学历、在校状态、毕业年份、到岗天数和实习期限。
- 列表字段采用集合完全匹配并计算 Precision、Recall 和 F1。
- 标准答案之外的预测称为“严格额外项”，不直接称为幻觉。

### 2. 归一化匹配

- 统一全角/半角、大小写、空格和标点。
- 应用 `data/normalization_aliases.json` 中经过人工审核的字段级映射。
- 支持一对多映射，例如一条复合描述可对应多个标准标签。
- 不使用不可解释的自动语义阈值，保证每个匹配都可以追溯。

### 3. 原文依据检查

归一化后仍属于额外项的预测会继续检查招聘原文：

- `source_supported_extras`：未匹配标准标签，但原文中有直接文字依据，需要人工判断是标注粒度还是字段归属问题。
- `potential_unsupported`：标准答案和原文中均未找到直接依据，进入人工复核队列。

“潜在无依据”不是最终幻觉结论。只有人工复核后，才能将其认定为真正幻觉。

## 防止评测规则过拟合

每条同义词规则都必须：

1. 指定所属字段，不能跨字段任意替换。
2. 由人工核对原文与标准答案后加入。
3. 保留严格指标，用于观察归一化规则带来的分数变化。
4. 在新增岗位数据上再次验证，不能只依据当前9条样本得出泛化结论。

## 输出文件

- `results/evaluation_v2_metrics.json`：规则方法与大模型方法的严格、归一化和原文依据指标。
- `results/error_analysis.jsonl`：逐岗位、逐字段的同义匹配、原文支持额外项、潜在无依据项和遗漏项。
