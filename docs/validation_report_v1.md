# 冻结验证集首轮盲测报告

版本：v1.0  
验证日期：2026-10-18  
验证集：`data/validation/validation_dataset.jsonl`（9条）  
对比方法：关键词规则v1、DeepSeek Flash + Prompt v1  
评测器：Evaluator v2

## 1. 实验约束

验证集与开发集完全分离。运行首轮盲测前，没有根据这9条岗位修改规则、提示词或归一化别名。规则与大模型预测分别保存在 `results/validation/`，未覆盖开发集实验结果。

后续标注审计确认：本批采集对象全部是实习岗位，原标准答案中4条 `employment_type: null` 与采集范围冲突。报告中的用工类型及宏平均准确率已按修正后的标准答案重新计算，预测文件保持不变。

## 2. 总体结果

DeepSeek明显提高了召回率和总体F1，但会把较长要求拆成许多细粒度短语，导致严格精确率偏低。规则方法只预测出5个列表项，因此所谓80%的“严格额外项率”只对应4个额外项，不能单独解读为严重幻觉。

## 4. 列表字段表现

DeepSeek各字段严格F1：

| 字段 | Precision | Recall | F1 |
| --- | ---: | ---: | ---: |
| 必备硬技能 | 10.96% | 21.05% | 14.41% |
| 必备工具 | 44.44% | 40.00% | 42.11% |
| 优先硬技能 | 14.81% | 40.00% | 21.62% |
| 优先经历 | 16.67% | 20.00% | 18.18% |

主要误差不是遗漏原文，而是标签粒度和字段归属不一致：

- 标准答案使用“AI快速原型开发”，模型输出“AI快速搭建可运行原型”。
- 标准答案使用“PRD撰写”，模型输出“产品需求文档撰写”。
- 标准答案将Python归入工具，模型有时同时放入硬技能。
- “Oracle或MySQL”这一或关系被模型拆成两个标签。
- 专业背景、软技能和项目经验被放入硬技能或优先硬技能。

现有归一化别名表完全来自首批开发集，因此本次验证的归一化F1仍为19.00%，没有高于严格F1。这说明别名表过拟合首批9条数据，尚未形成可泛化的概念层标准。

## 5. 原文依据人工复核

评测器自动标记了9个“潜在无依据”短语，包括“产品需求文档撰写”“testcases测试用例设计”“数据收集”“数据报表维护”等。逐项对照后，这些内容均能在原文中找到直接或近似表述，自动检测失败的原因是词序变化、插入助词和短语扩展。

因此：

- 自动潜在无依据率：7.09%。
- 本轮人工确认的真正无依据项：0个。
- 当前groundedness检查适合作为人工复核候选生成器，不能直接作为最终幻觉率。

## 6. 结论与下一版优先级

首轮盲测达到“发现系统性问题”的目的，但当前指标不适合作为最终模型能力结论。下一版应按以下顺序改进：

1. 扩展模型输入结构，把页面顶部元数据显式传入提取器。
2. 升级输出Schema，支持`graduation_year.exact`和“或”关系工具标签。
3. 收紧Prompt的标签粒度与字段边界，减少把软技能和背景写入硬技能。
4. 建立概念级标准词表，而不是继续为单个样本追加别名。
5. 改进原文依据算法，支持词序变化、助词和同义短语，并保留人工审核环节。
6. 修改后应把当前验证集转为调优集，再另外收集全新的最终测试集，避免重复使用同一批数据报告泛化结果。
